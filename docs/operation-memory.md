# 操作触发记忆召回与媒体回复缓冲

实现分支：`feat/scoped-notes`。本次基于该分支既有元数据与范围检索实现扩展，未修改在线 profile。

## 召回时点

1. 入站：由附件类型、视频链接与明确任务词生成操作标签；和用户原文共同检索。标签只增加候选，不排除未标记或其他标签的内容背景。
2. 工具返回：`tools/post-execute` 全局监听只处理映射表中的媒体工具，再用当前问题与工具公开的 text/title 检索。任意工具参数、shell结果和错误原文不作为检索输入。项目权限不从工具文本扩大。
3. 同轮：按文件、小节及正文哈希去重；同一正文不重复注入，新版本正文可重新召回。初次媒体召回最多使用总字数预算60%，后续使用剩余额度。完整渲染块计入预算。
4. 媒体回复：首次生成前启用文字缓冲；`agent/turn-stopping` 根据失败、截断、覆盖和音轨状态追加最多一次修订提示。普通未启用缓冲的聊天保持原路径。

## 参数示例

```yaml
operations:
  - media.video.inspect
  - media.audio.transcribe
```

保存工具可传 operations 数组。旧笔记无需迁移：词面与语义路线仍可召回，操作别名还会为未打标签的旧经验提供内容词。

已映射操作：media.video.inspect、media.video.fetch、media.video.frames、media.image.inspect、media.image.origin、media.audio.transcribe；媒体工具凭证失败另加 credentials.resolve.missing。未知工具不自动解析其输出。

## 边界

- 1200ms检索超时后继续正常执行；迟到结果不得提交去重、预算或注入账本。不会修改固定system前缀。笔记完整渲染块受回合总预算限制；工具执行事实另有每轮1200字/16事件上限。
- 普通轮已开始发送后才补入媒体时，不撤回已发送文字，也不强行晚启缓冲；保留操作召回并记录本轮无法发送前缓冲。
- 审计失败的原稿存入独立最多32会话的内存诊断区，清理已结束门禁以免影响下一轮；该降级不是持久保证。
- 本次真实媒体结果与历史笔记分开标记，历史背景不充当已观看/已听取的证据。
- 发送前处理是有界证据提醒与少量一致性检查，不是完整语义审稿器，也不保证识别所有无依据论断。
- 原生图片不要求必须调用图片解析工具；没有工具调用不等于没有看图。
- 仅缓冲经outbound路由的助手文字。qqbot_send_file等工具内部直接发送的媒体、配文以及其他通道不在此缓冲覆盖范围。
- 审阅原稿在内存保留，turn/end后存入用户目录 `.dsh/qqbot-media-review/`。记录只证明草稿和审阅状态，不证明QQ送达；送达仍以发送结果为准。该目录含聊天内容，不应提交版本库。
- 当前没有重启恢复中断审阅的完整流程；持久记录用于诊断，不自动重发旧原稿。
- 范围安全修正：目录会话归属不可由正文改写，未知检索身份默认共享范围，替代关系不得跨不兼容范围全局压制，歧义裸标题不建立替代边，冲突提示不暴露不可见目标。
