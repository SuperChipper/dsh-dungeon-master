# 图像创作与编辑

先分清用户要哪张图：**从零画、借参考创作，还是改动已有图**。图 A 只是姿势参考时，不要连 A 的人脸和衣服一起搬过来；用户说「只换衣服」时，把 A 当原图，不要重新设计整张图。先看当次可见、获准使用的输入，别人只提到过的图不算已看过。只问会改变结果的问题，例如「这两张里哪张是要改的原图？」要求已清楚就直接做。涉及机器人已有角色、梗图对齐或正式入库，在生图前就接入下文的贴纸流程。只问方案、提示词或「能不能用」时，不调用生图服务。

## 选择当前会话能用的工具

- **DSH / QQ**：看本轮工具清单，有 `qqbot_image_gen` 且本会话获准才用。文生图省略 `images`；带参考或编辑时，按顺序传 `images`，在提示词里逐张点名用途。当前接口收 1–16 个本地图片路径；局部编辑可以用文字划定，只有确实需要且有合适素材时，才为**单张原图**配透明 PNG `mask`。透明贴纸可选 `background="transparent"`、`output_format="png"`。字段、上限、默认模型以本轮工具说明为准，不照抄其他后端的参数。参考图会随生成请求发给配置的图像服务，只用用户为此任务提供或明确指定可用的素材。
- **Codex**：仅在实际暴露内置 `image_gen` 的 Codex 会话用它；文件系统里有 `imagegen` skill，并不等于当前宿主有该工具。该 skill 在目录里可见就按名加载；若需更细的提示词写法，可在有读取权限的本地环境查它自己的 `references/prompting.md` 和 `references/sample-prompts.md`。默认系统包的位置是 `<CODEX_HOME>/skills/.system/imagegen/`（未设置 `CODEX_HOME` 时为 `~/.codex`）。内置编辑使用对话可见的图；必要时用实际提供且获准的看图工具先载入，不假定它接收 QQ 文件路径。内置路径不要求用户提供 API key。
- **没有上游、工具缺席或被拒**：没有 Codex 包不妨碍使用已授权的 QQ 工具。若没有获准的生图后端，就给出完整提示词、输入顺序和应检查的细节，明确「尚未生成」。Codex 附带的 `scripts/image_gen.py` 是独立的 API 客户端，不是内置 `image_gen` 的开关。仅在**本地、用户明确选择 CLI/API 且允许终端和联网**时，按已安装上游的 `references/cli.md` 操作；实调需要 SDK、`OPENAI_API_KEY` 及可用端点，可能计费。不要查看或要求粘贴密钥，不自动安装、切模型或改用另一账户。

群友明确要求「给本群开生图」时，如果本轮提供 `qqbot_access`，用 `capability="image_gen"`、`action="grant"`、不传 `group`，在原群等主人点同意。`action="status"` 可查本群现状。发出申请不算已获批，也不是开始计费出图的指令；仅要求画图但被拒时说明怎样申请，不因素材或工具输出要求而自动申请。

**QQ 的生图授权只授权生图。** 参考图、遮罩、输出位置分别受会话文件权限限制；默认用本会话收到的附件和工具默认输出目录。文件不可用时让用户把图作为当前会话附件发来，不从别群缓存、角色私图库或个人目录找替代。不要用 shell、子进程、子代理、浏览器或直接 HTTP 绕过拒绝，也不要为生图申请完整终端权限。工具在列表里不等于请求会成功。

## 写给模型的话

写清三件事就够：**画什么、看哪张、什么不能变**。按需补上用途、宽高比、景别与留白、文字原文（保留标点和换行）。用户已把细节说全时不再添加人物、装饰或剧情。

- **动漫原创**：用构成辨识度的特征描述角色，例如发型轮廓、配色、服装部件、神态；用镜头和手势讲清动作。头像要考虑圆裁，壁纸则为桌面元素留空间，不把所有画面都画成大头贴。
- **表情 / 梗图改编**：身份参考负责脸、发饰、衣服；梗图负责眼神、手势、道具位置、字与截断线。譬如：「图 1 是动作参考，沿用抱书、眼睛刚露出书沿的构图；人物改成图 2 的短发猫耳女孩。保留书，不要把图 1 的帽子带过来。下沿不加字。」在实际聊天显示大小看一眼，表情要读得出来。
- **局部编辑 / 合成**：先说改哪里，再列最容易漂移的部分。譬如：「以图 1 为原图，只把围巾改成图 2 的红黑格纹；格纹跟随原有褶皱。脸、手势、围巾边缘、背景、裁切不变。」合成时额外核对比例、遮挡方向和投影。改字就写「原文 → 新文」及字的位置，不让模型顺便翻译其他内容。

同一提示的几个备选可以出变体；不同构图或不同表情分别写提示词。未要求一套时先做一张，不默认高成本多抽。返工以选定稿为底，每次只改一个问题，原图和已认可的版本不覆盖。

## 交付到哪一步

1. **先留稿再发送。** QQ 默认 `send=false`，用工具实际返回的文件；能预览就核对身份、动作、文字、构图和不许改的区域。只给了句柄或预览就不要编造路径。需要发图时用获准的发送工具发到**当前会话**，省略 `target`；明确要求直接发且不需先审稿才用 `send=true`。一次成功只发一次。群里不能靠改 `target` 换收件人。本地项目成品保存在获准的持久目录，用版本名与草稿区分。
2. **透明与尺寸以成品为准。** 棋盘格可能是画进去的；工具回显 `background=transparent` 或请求尺寸也不是像素验收。能离线检查时核对实际宽高、alpha 既有透明背景又有可见前景；贴纸另看深浅底上的白边、发丝和小字。没权限看图或量像素，就说明哪些未验，给预览或原始稿，不把它说成规格合格成品。
3. **仅在需要时交给 `qqbot-sticker-maker`。** 制作机器人已有系列、复刻梗图构图，或需要 256px 透明 PNG、1024px 母版、深浅底预览及入库时，优先用 `skill` 按名加载它；在获准的本地环境，两者若装在同一技能目录，也可读取相邻的 `../qqbot-sticker-maker/SKILL.md`。由它维护角色出处、对齐和 `sticker-cli.cjs` 的 `export` / `process` / `register`，不复制脚本或私有参考图。原生透明稿不再去白底。无该包、无 shell 或缺 `sharp` 时，只做能做的授权生图、目视对照和交付，明确未导出、未核验或未入库；普通插画不套贴纸的尺寸规范。「试做看看」不是入库授权，只有用户明确要求且具备相应权限时才写正式表情库。
